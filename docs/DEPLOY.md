# النشر والتشغيل

## الخيار الموصى به: Render (حوالي 13 دولارًا شهريًا)
لماذا Render؟ لأنه يوفر HTTPS تلقائيًا، وخدمة تعمل دائمًا بلا نوم، وقاعدة PostgreSQL بنسخ احتياطي مستمر، ونشرًا من GitHub بضغطة. لا تحتاج أي أوامر برمجية يومية.

### المتطلبات (مرة واحدة)
1. حساب GitHub يحتوي مستودعًا خاصًا (private) فيه كود «نداء».
2. حساب على render.com مع بطاقة دفع (للخطة الدائمة).

### الخطوات
1. **ارفع الكود إلى GitHub**: أنشئ مستودعًا خاصًا فارغًا باسم `nidaa`، ثم ارفع محتوى هذا المجلد إليه. الأسهل أن تربط GitHub بجلسة Claude وأدفع الكود أنا. أو استخدم «Upload files» في صفحة المستودع وارفع محتوى ملف `nidaa-source.zip`.
2. في Render اختر: **New → Blueprint** ← اختر المستودع ← **Apply**. سيقرأ Render ملف `render.yaml` وينشئ:
   - خدمة ويب `nidaa` (خطة Starter، منطقة فرانكفورت)،
   - قاعدة بيانات `nidaa-db` (PostgreSQL 16، خطة Basic-256mb)،
   - متغير `SETUP_TOKEN` بقيمة عشوائية.
3. انتظر حتى تصبح الحالة **Live** (من دقيقتين إلى خمس دقائق). الرابط سيكون بالشكل: `https://nidaa-xxxx.onrender.com`.
4. افتح من صفحة الخدمة: **Environment ← SETUP_TOKEN ← انسخ القيمة**.
5. على اللابتوب افتح `https://nidaa-xxxx.onrender.com/setup`، والصق رمز الإعداد، ثم أدخل اسم المحل والفرع ومكان الاستلام وحساب المالك.
6. أكمل قائمة «الإعداد الأول» التي تظهر بعدها. التفاصيل في [DEVICES.md](DEVICES.md).

> بعد الإعداد الأول تُغلق صفحة `/setup` تلقائيًا، ولا يمكن استخدامها مرة أخرى.

### نطاق خاص (اختياري)
من صفحة الخدمة: **Settings ← Custom Domains**. أضف مثلًا `nidaa.yourcafe.com` وأضف سجل CNAME عند مزود النطاق. بعد ذلك أضف في **Environment** المتغير `PUBLIC_URL=https://nidaa.yourcafe.com`. **انتبه:** رموز QR المطبوعة سابقًا تبقى على الرابط القديم، فلا تغيّر النطاق بعد بدء التشغيل الفعلي.

### التحديثات
أي دفع إلى فرع `main` يُنشر تلقائيًا. ترحيلات قاعدة البيانات تُطبَّق عند بدء التشغيل، وهي محمية بقفل يمنع تشغيلها مرتين.

## المراقبة
- `GET /healthz`: يستخدمه Render لإعادة تشغيل الخدمة إذا تعطلت.
- **الإعدادات ← التنبيهات وحالة النظام**: إحصاءات الإرسال لآخر 7 أيام وآخر الأخطاء الخاصة بالفرع.
- سجلات الخادم في Render (Logs) بصيغة JSON. رموز العملاء مختصرة فيها (`/o/AbCd…`)، والكوكيز وترويسات Authorization محذوفة.
- يمكن إضافة تنبيه توقف مجاني بمراقبة `/healthz` من خدمة مثل UptimeRobot.

## النسخ الاحتياطي والاستعادة
- قاعدة Render المدفوعة فيها **استعادة لأي لحظة (PITR) خلال آخر 3 أيام** في مساحة العمل Hobby (7 أيام في الخطط الأعلى)، إضافة إلى نسخ منطقية قابلة للتنزيل. حسب [وثائق Render](https://render.com/docs/postgresql-backups).
- **الاستعادة**: من صفحة القاعدة اختر **Recovery** ← اختر الوقت ← تُنشأ قاعدة جديدة. اربط `DATABASE_URL` في خدمة `nidaa` بها، ثم أعد التشغيل.
- **نسخة يدوية شهرية (اختيارية)**: انسخ External Database URL من صفحة القاعدة، ثم نفّذ على أي جهاز فيه PostgreSQL:
  `pg_dump "<External URL>" -Fc -f nidaa-$(date +%F).dump`
- مفاتيح VAPID محفوظة داخل القاعدة نفسها، فالاستعادة تُبقي اشتراكات التنبيه صالحة.

## بدائل الاستضافة
- **أي خادم Docker** (مثل Fly.io أو Railway أو VPS): استخدم `Dockerfile` واضبط `DATABASE_URL` و`PUBLIC_URL` (HTTPS) و`SETUP_TOKEN`. إذا لم يكن الخادم خلف وكيل عكسي موثوق، اضبط `TRUST_PROXY=false` حتى لا يمكن تزوير عنوان IP في محدد المعدل.
- **قاعدة خارجية** (مثل Neon أو Supabase): اضبط `DATABASE_SSL=true`. **تنبيه:** الخادم يستعلم كل 15 ثانية للصيانة، فلا تبقى القاعدة «نائمة». هذا يستهلك ساعات الحوسبة في الخطط المجانية بسرعة، لذلك لا ننصح بها للتشغيل الدائم.
- **الخطة المجانية في Render غير مناسبة**: الخدمة تنام بعد 15 دقيقة، والقاعدة المجانية تُحذف بعد مدة محدودة ولا نسخ احتياطي لها.

## متغيرات البيئة
| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `DATABASE_URL` | نعم | رابط PostgreSQL |
| `PUBLIC_URL` | في غير Render | الرابط العام الذي يوضع في QR (HTTPS). في Render يؤخذ تلقائيًا |
| `SETUP_TOKEN` | نعم عند النشر | يحمي صفحة الإعداد الأول |
| `RETENTION_DAYS` | لا (الافتراضي 90) | بعدها تُحذف الطلبات وسجلاتها |
| `DATABASE_SSL` | لا | `true` للقواعد الخارجية |
| `TRUST_PROXY` | لا (الافتراضي true) | `false` إذا لم يكن الخادم خلف وكيل |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | لا | تُولَّد تلقائيًا إذا تُركت |
| `APNS_KEY_ID` / `APNS_TEAM_ID` / `APNS_PRIVATE_KEY` / `APNS_BUNDLE_ID` | لمسار App Clip فقط | انظر [ios/README.md](../ios/README.md) |
| `APPLE_APP_ID` | لمسار App Clip | `TEAMID.bundle.Clip` لملف apple-app-site-association |
| `APPLE_STORE_APP_ID` | اختياري | لإظهار بطاقة App Clip في سفاري |

## التشغيل المحلي (للمطورين)
```bash
npm ci
createdb nidaa              # PostgreSQL 14 فأحدث
cp .env.example .env        # عدّل DATABASE_URL
node --env-file=.env src/server.js
# الاختبارات (تحتاج قاعدتي nidaa_test و nidaa_test2)
npm test && npm run test:e2e
```
